# Storix — Wave 3: league feed, upgrade celebrations, admin journal (spec)

## 1. Goal
- **I-05 Fil de la ligue** (proposal A "Le fil sous le booster"): on Home, under the booster widget, "Dans la ligue" replaces "Révélations récentes". Sentences say who did what; what happened since my last visit is split out; legendary/mythic moments are highlighted; small events are grouped ("×3"); filter chips Tout / Tirages / Photos / Exploits; 8 rows on Home, "Tout voir" opens the full feed over 30 days.
- **I-08 Fêter les améliorations** (proposal A "Le sacre"): after a personal-tier promotion the card rises to the centre, its aura switches from the old tier to the new one with a glare, a ★ stamps the corner (sound `stamp`), then "Rare → Épique ★", "Partager" (Flex) and "Super". Friends can send one "Bravo" from the feed row.
- **I-09 Journal admin** (proposal A "Le registre"): a "Journal" tab in Admin reading `audit_log`; French sentences grouped by day, one colour per category, expandable detail, failed reset codes grouped in red; category chips + "⋯" filter sheet (member + period).

Design source: https://claude.ai/artifact/ULor8Za51zWVyQgkso4eqd (local `/private/tmp/claude-501/-Users-tristanhourtoulle--paradev-sessions-victorious-hamster-f823c5be/ff466f9b-8cfa-4957-a0b3-c205181e635e/scratchpad/wave3/vague-3.html`). The implementation reproduces the picked proposals exactly.

Base: this wave is stacked on wave 2 (`feat/wave2-members-emblems`: `member_emblems`, emblem unlock banner/gate, member pages `/l/$leagueId/members/$userId`, migration 0016). Branch `feat/wave3-feed-celebrations` is rebased onto main after wave 2 merges; migrations start at **0017**.

## 2. Frozen user decisions (2026-11-10)
- I-05 A, I-08 A, I-09 A.
- I-05 options: events = pulls Epic+, every premium booster, discoveries, new photos entering the pool, ★ upgrades, emblems, member arrivals, cards becoming Legendary/Mythic at recompute; no Commons, no duplicates. Grouping: same member + same type within 3 h = one row "×N"; Legendary/Mythic never grouped. 30 days in "Tout voir", 8 rows on Home. "Since your last visit" stored server-side. My own actions are shown but not counted as new. Dedicated events table written at action time; grouping and privacy at read time.
- I-08 options: one "Bravo" per person, visible in the feed, no push. Tapping skips to the final text; honours reduced motion. "Partager" at the end in "Flex" style with the new ★ tier. Foil upgrade is celebrated too (short version: glare + `burst`) and gets a feed row. Mythic ★ uses the same animation with the rainbow ring and a longer sound, and is the only case with a league-wide banner.
- I-09 options: owner + admins only. "Économie" (recycle, convert, foil, promotion, craft) hidden by default, toggle in the filter sheet. Account actions (display name, avatar) of current league members shown under "Comptes". Failed reset codes grouped per member per hour, in red, with a red dot on the Journal tab until an admin opens it. Keep everything; default period 30 days. Departed members shown with their name + "(parti)"; deleted accounts "Ancien membre".

## 3. Decisions made by the planner
| # | Decision | Why |
|---|---|---|
| D1 | New table `league_events(id uuid, league_id, actor_id text null, type text, card_id uuid null, tier card_tier null, payload jsonb, dedupe_key text null unique, visible_at timestamptz, created_at)`; index `(league_id, visible_at desc, id desc)`. | Dedicated table per user choice; `visible_at` lets a published photo appear only when it enters the pool. |
| D2 | Event types (`LEAGUE_EVENT_TYPES` in shared): `booster_opened`, `card_pulled` (Epic+ or discovery), `card_published`, `card_promoted`, `card_foiled`, `emblem_unlocked`, `member_joined`, `card_tier_reached` (Legendary/Mythic at recompute). | Exactly the adopted event list. `booster_opened` exists to render "Tom, Léa et 4 autres ont ouvert 17 boosters · meilleure carte : Épique" and the premium flag. |
| D3 | Payload never stores titles or image URLs: only ids, tiers, flags (`isPremium`, `isDiscovery`, `fromTier`, `toTier`, `emblemId`, `openingId`, `count`). | Privacy is resolved at read time from the viewer's copies (reuse `withViewerCopies` + `toCollectionCard`): locked cards stay blurred with no title. |
| D4 | Idempotence: `dedupe_key` unique (`opening:<id>`, `pull:<openingId>:<slot>`, `publish:<cardId>`, `promote:<copyId>:<toTier>`, `foil:<copyId>`, `emblem:<leagueId>:<userId>:<emblemId>`, `join:<leagueId>:<userId>:<joinedAt>`, `tier:<cardId>:<tier>:<computedAt>`), inserts use `ON CONFLICT DO NOTHING`. | Replays (booster idempotent requestId, worker retries) never duplicate rows. |
| D5 | Events are written in the same transaction as the source action: booster opening (`boosters.service.ts`), promotion (`stacks.service.ts`), foil (`copies.service.ts`), member join (`invitations.service.ts`), emblem award (inside `awardEarnedEmblems` in `packages/db`, so API and worker both emit), card publish (worker `card-publish.service.ts`, `visible_at = now + newCardDelayMinutes`), recompute (worker `rarity-recompute.service.ts`, only upward transitions into Legendary/Mythic). | User constraint. One shared `insertLeagueEvents(db, events[])` query in `packages/db/src/queries/league-events.ts` used by api and worker. |
| D6 | Grouping is a pure function `groupFeed(events, { viewerId, lastSeenAt, windowMs = 3h })` in `packages/shared/src/domain/league-feed.ts`. Rules: Legendary/Mythic pulls, `card_tier_reached`, `card_promoted` (needs its own Bravo) and `member_joined` are never grouped; `booster_opened` from any members in the same 3 h window collapses into one row (`actors`, `count`, `bestTier`, `hasPremium`); other types group per actor+type within 3 h with `count`. Rows carry `isNew = createdAt > lastSeenAt && actorId !== viewerId`. | Testable, one place for the anti-spam rule. |
| D7 | Filters: `Tirages` = booster_opened, card_pulled, card_tier_reached; `Photos` = card_published; `Exploits` = card_promoted, card_foiled, emblem_unlocked, member_joined. Server filters by type list. | Matches the chips. |
| D8 | API `GET /leagues/:leagueId/feed?filter&cursor&limit` (member). Reads raw events (`visible_at <= now`, last 30 days) newest first, cursor `(visible_at, id)`, raw page 120, groups server-side with D6, returns `{ rows, nextCursor, lastSeenAt }`. Home asks `limit=8` rows; "Tout voir" pages. A group may split across pages; acceptable at this scale. | Grouping needs neighbours; doing it on the server keeps the web thin and the payload private. |
| D9 | Table `league_reads(league_id, user_id, feed_seen_at, mythic_banner_seen_at, journal_seen_at)` PK (league_id, user_id). `POST /feed/seen` sets `feed_seen_at = now` when the user leaves Home (on unmount/visibility hidden, debounced); the separator uses the value read at mount. | One small table for all three "seen" states of this wave. |
| D10 | Bravo: table `event_bravos(event_id, user_id, created_at)` PK (event_id, user_id); `PUT /feed/events/:eventId/bravo` (idempotent), only on `card_promoted` events of the same league, not on your own event. Rows return `bravoCount` and `hasBravoed`. No push. | One per person, visible in the feed. |
| D11 | Celebration (`promotion-celebration.tsx`): full-screen overlay after promote success; phases rise (400 ms) → aura switch with `aura` sound of the new tier + glare (700 ms) → ★ stamp with `stamp` (300 ms) → text + "Partager" + "Super". Tap anywhere jumps to the final phase; `prefers-reduced-motion` shows the final phase directly. Foil: short variant (glare + `burst`, final text "Ta copie est brillante"). Mythic ★: rainbow ring (`.t-M`) and the longer mythic aura sound. "Rejouer l'animation" link in the promotion sheet is not built (artifact demo control only). | Matches proposal A; reuses existing sound requests, no new files. |
| D12 | "Partager" opens the existing share sheet with style preselected to `flex` (via `writeShareStyle('flex')` before opening) and the copy's new personal tier. | Reuse the existing PNG generator. |
| D13 | Mythic ★ league banner: `GET /feed/highlights` returns `card_promoted` events with `toTier = 'mythic'` newer than `mythic_banner_seen_at` (not mine); a `MythicBannerGate` in `l.$leagueId.tsx` shows the top banner "Léa a fait passer « … » Mythique ★" with Bravo; dismiss → `POST /feed/highlights/seen`. Suspended with booster stage, add screen, onboarding, whats-new and the emblem banner (same pattern as wave 2 gates). Locked card → no title ("une carte"). | Only league-wide banner. |
| D14 | Journal API `GET /leagues/:leagueId/audit?category&actorId&from&cursor` (`requireLeagueRole('admin')`, owner included). Categories from pure `auditCategory(action)` in shared: members, cards, settings, security, economy, accounts. Default excludes `economy` and uses `from = now - 30 days`. Account rows = `league_id IS NULL` and `actor_id` is a current member of this league. Page size 50, cursor `(created_at, id)`. Returns `{ entries, nextCursor, hasUnseenAlerts }`. | Matches the options; admins don't see other leagues. |
| D15 | Failed codes: pure `groupAuditEntries(entries)` merges `reset_code.failed` with the same target within 1 h into one entry `{ count, times[] }`. `hasUnseenAlerts` = a failed code newer than `journal_seen_at`; `POST /audit/seen` on tab open. Red dot on the Journal tab. | Option adopted. |
| D16 | Sentences are built on the web by `audit-sentence.ts` (one formatter per action, 34 actions, French), detail lines from metadata (settings before/after, tier pins). Names: current member → name; former member → name + " (parti)"; null actor → "Ancien membre". The API returns `{ actor: { userId, displayUsername, isFormer } }` resolved via `user` + `league_members`. | Copy belongs to the UI; the API stays generic. |
| D17 | Backfill in migration 0017: `league_events` from the last 30 days of `booster_openings` (booster_opened), `booster_pulls` Epic+ or discovery (card_pulled), active `cards` created (card_published), `league_members.joined_at` (member_joined), `member_emblems` (emblem_unlocked) with their dedupe keys. Promotions/foils/recompute not backfilled. `league_reads` empty → everything older than now counts as seen: backfilled rows use `feed_seen_at` default = migration time via `INSERT … SELECT` for every member. | The feed isn't empty at launch and nobody gets 30 days of "new". |
| D18 | Rate limits: feed reads use the default read guard; bravo uses `cardAction`; seen endpoints `cardAction`; audit read `adminAction`. | Same as existing routes. |
| D19 | Web structure: `apps/web/src/features/league-feed/` (api, queries, `use-league-feed`, `use-bravo`, components `feed-section`, `feed-row`, `feed-filters`, `mythic-banner-gate`), route `l.$leagueId.activity.tsx` ("Tout voir"); `apps/web/src/features/cards/components/promotion-celebration.tsx`; `apps/web/src/features/audit/` (api, queries, `audit-sentence.ts`, components `journal-panel`, `journal-row`, `journal-filter-sheet`). `recent-reveals.tsx` and `/reveals` route are removed once the feed replaces them (check no other consumer). | Feature folders. |
| D20 | Tests: `league-feed.test.ts` (4 cases: 3h actor grouping, legendary never grouped, booster_opened cross-member aggregate, isNew excludes own), `audit-groups.test.ts` (2 cases: failed codes within 1 h merged, category mapping default excludes economy). | Few tests on pure logic only. |

## 4. Design

### 4.1 Shared
- `domain/league-feed.ts`: `LEAGUE_EVENT_TYPES`, `FEED_FILTERS` map (D7), `groupFeed` (D6), `FEED_WINDOW_DAYS = 30`, `FEED_GROUP_WINDOW_MS`.
- `domain/audit.ts`: `AUDIT_CATEGORIES`, `auditCategory(action)`, `groupAuditEntries` (D15). `AUDIT_ACTIONS` moves to shared or is re-exported (the db schema keeps its `$type`).
- `schemas/league-feed.ts`: feed query (filter, cursor, limit), `feedRowSchema` (discriminated by `kind`, with `card?: CollectionCardSummary`, actors `{userId, displayUsername}`, `count`, `tier`, `isPremium`, `isDiscovery`, `fromTier`, `toTier`, `emblemId`, `bravoCount`, `hasBravoed`, `isNew`, `at`), page response; highlights response.
- `schemas/audit.ts`: query (category list, actorId, from, cursor), entry (id, action, category, actor, target, metadata, createdAt, count?, times?), page response with `hasUnseenAlerts`.

### 4.2 DB (`packages/db`)
- Schema files `league-events.ts`, `league-reads.ts`, `event-bravos.ts`; migration 0017 (tables, indexes, backfill D17).
- `queries/league-events.ts`: `insertLeagueEvents` (ON CONFLICT DO NOTHING on dedupe_key). `awardEarnedEmblems` (wave 2) calls it for newly inserted emblem ids.

### 4.3 API / worker
- Emitters (D5) in boosters, stacks (promote), copies (foil), invitations (join) services; worker publish + recompute.
- `features/league-feed/` routes/service/repository: feed, seen, bravo, highlights, highlights seen. Repository loads raw events + bravo counts + viewer copies in batched queries (no N+1), service groups and resolves privacy.
- `features/audit/`: add routes/service; repository `listAuditPage`, `markJournalSeen`, `hasUnseenFailedCodes`.

### 4.4 Web
- Home (`l.$leagueId.index.tsx`): `FeedSection` replaces `RecentReveals` under the booster widget (header "Dans la ligue" + "Tout voir", chips, "Depuis ta dernière visite" separator, day groups "Aujourd'hui/Hier/date", big rows for Legendary/Mythic/premium tinted with the tier colour, grouped "×N" rows, avatars). Row tap → card vitrine, or member page for joins/emblems (former members not linked).
- `/l/$leagueId/activity`: same section, paginated, 30 days.
- Celebration overlay wired in the promotion and foil sheets' success handlers; Mythic banner gate in the league layout.
- Admin: `TAB_IDS` gains `journal`; Segmented label "Journal" with red dot; `JournalPanel` with chips (Tout / Membres / Cartes / Réglages / Sécurité), "⋯" opens a filter sheet (member chips, period 7/30/Tout, Économie switch, Comptes included in Tout) with the pinned footer (`Réinitialiser` / `Voir N lignes`), rows grouped by day, coloured icon per category, tap expands the detail, failed codes red.

## 5. Out of scope
Push notifications for feed events; reactions other than Bravo; editing/deleting events; purging old events; journal export.

## 6. Risks
- Rebase on wave 2 (league layout gates, `awardEarnedEmblems`, member routes, migration numbering 0017).
- Extra inserts in hot transactions (booster opening writes 1–6 events): small, indexed, acceptable at 5–30 members.
- Grouping across page boundaries can split a group in "Tout voir".
- 34 sentence formatters: missing metadata on old audit rows must degrade to a generic sentence, never crash.
- Removing `/reveals`: verify no other consumer (whats-new illustration uses static data).

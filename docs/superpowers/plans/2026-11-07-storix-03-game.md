> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.
>
> **Commits:** every task ends with a commit step, but `git add` / `git commit` run ONLY after the user's explicit go-ahead at execution time. Without it, stop at the step and report. Exception: Task 15 merges and pushes to `main` (authorized by Tristan for the Plan 3 deploy).

**Goal:** Members earn timed boosters, open them in an animated reveal (rarity glow before the flip), own copies frozen at their mint tier, convert duplicates to dust, recycle / craft / upgrade to foil, react to cards, and see a collection made only of their own copies plus locked "???" silhouettes; card rarity is computed by a nightly + on-change engine with hysteresis, cold start and admin precedence, and the whole thing ships to Railway.

**Architecture:** Every game rule is a pure function in `packages/shared/src/domain` (rarity engine, booster stock, seeded RNG + draw, pity, dust economy), unit-tested with Vitest. The API opens a booster in one transaction that locks the member's wallet row, replays an existing opening for the same client `requestId` (idempotency), computes the lazy stock, draws with a CSPRNG seed fed into a deterministic PRNG, settles copies (new / higher-tier replace / duplicate → dust), claims "discovered by", updates pity and logs seed + table version + pool digest. The worker recomputes a league's rarity in a debounced pg-boss job (after each new card, nightly, once at startup) and historizes tier changes. The collection and card detail endpoints are ownership-aware: a card the viewer does not own is serialized through a strict "locked" schema that has no title and no image URL, so the web can only render a thumbhash blur.

**Tech Stack:** Plans 1-2 stack + `motion` (LazyMotion, `m`, `domAnimation`, `MotionConfig`) for the reveal. No other new dependency.

**Spec:** `docs/superpowers/specs/2026-11-07-storix-design.md` (sections 4.1-4.4, 5.1-5.5, 6.2, 6.4, 6.5). Roadmap: `docs/superpowers/plans/2026-11-07-storix-roadmap.md`. Conventions: Plans 1 and 2 in the same folder. Visual source: direction A mockup `Main.dc.html` (`.hero`, `.pack`, `.pack-foil`, `.pack-logo`, `.pips`, `.pip`, `.pity*`, `.bar*`, `.dust`, `.card.back`, `.back-face`, `.g-*`, `.phone.stage`, `.reveal*`, `.badge-new`, `.hand*`, `.dup`, `.hint`, `.card.locked`, `.count-big`, `.reacts`, `.react`, `.actions` — copy the values from that file; the pack logo text is `STORIX`, not `CLIQUE`).

**User decisions that override the spec (binding):**
1. The Collection lists ONLY the viewer's own copies. Every other `active` league card appears LOCKED: thumbhash-only heavy blur, tier color and tier label visible, title shown as `???`. The API never sends a media URL or a title for a card the viewer does not own (list, detail, reveals). A locked card opens a locked detail without image.
2. The author does NOT receive a copy of their own card (overrides 5.1 "the author receives a copy immediately"); they pull or craft it like everyone else.
3. No trades (the Échanges tab stays "bientôt"). Wonder Pick, wishlist, duels, sets/seasons are out.

## Review Focus

1. Double tap on "Ouvrir", a network drop during the open request, or a reload in the middle of the reveal: exactly one booster is consumed and the same five cards are shown again (Task 8 parallel same-`requestId` curl; Task 12 offline + reload check).
2. A card the viewer does not own leaks nothing: no `/media/` URL and no title in the collection, the detail, the recent reveals, nor in the service worker API cache written by Plan 2 before this deploy (Task 9 grep check; Task 14 cache-version check; Task 15 production grep).
3. A young or tiny league: zero cards, all cards younger than 12 h, only commons, or no Epic for a pity guarantee: the booster is refused with a clear French message without consuming stock, or falls back to the nearest available tier (Task 2 fallback tests; Task 8 curl checks; Task 11 empty-pool message).
4. Spending races: "Recycler" tapped twice, "Fabriquer" in two tabs, a booster opened while crafting: dust never goes negative, never two normal copies of one card, never a lost booster (Task 1 decision tests; Task 10 parallel curl checks).
5. Time: the countdown reaching zero while the screen is open or the app was backgrounded for hours, stock already at max, a phone with a wrong clock: the server state wins and the stock never exceeds the max (Task 1 stock tests incl. clock skew; Task 11 one-minute-cadence browser check).

  - `dust.ts`: `COPY_VARIANTS = ['normal','foil'] as const`; `type CopyVariant`; `DUST_VALUES: Readonly<Record<CardTier, number>> = { common: 5, uncommon: 10, rare: 25, epic: 100, legendary: 400, mythic: 1000 }`; `FOIL_DUST_MULTIPLIER = 2`; `CRAFT_COST_MULTIPLIER = 4`; `FOIL_UPGRADE_COST_MULTIPLIER = 2`;
    - `dustValue(tierAtMint: CardTier, variant: CopyVariant): number`
    - `craftCost(currentTier: CardTier): number | null` (null for mythic)
    - `foilUpgradeCost(currentTier: CardTier): number`
    - `copyKey(cardId: string, variant: CopyVariant): string` (`${cardId}:${variant}`)
    - `type PulledCopyOutcome = 'new' | 'upgraded' | 'duplicate'`
    - `resolvePulledCopy(owned: CardTier | null, pulled: { tierAtMint: CardTier; variant: CopyVariant }): { outcome: PulledCopyOutcome; dust: number }` — no owned copy of that variant → `new`, 0; pulled tier > owned → `upgraded`, dust = `dustValue(owned, variant)` (the replaced copy is converted); else `duplicate`, dust = `dustValue(pulled.tierAtMint, variant)`.
    - `interface CopySettlement { cardId: string; variant: CopyVariant; tierAtMint: CardTier; outcome: PulledCopyOutcome; dust: number; isFirstCopyOfCard: boolean }`
    - `settleBoosterCopies(pulls: readonly { cardId: string; tier: CardTier; variant: CopyVariant }[], owned: ReadonlyMap<string, CardTier>): { settlements: CopySettlement[]; dustGained: number; owned: ReadonlyMap<string, CardTier> }` — `owned` keyed by `copyKey`, processed in order (a second pull of the same card in one booster sees the first); `isFirstCopyOfCard` = neither variant owned before this pull; returns a new map, never mutates the input.
    - `type CraftBlock = 'owned' | 'not_craftable' | 'provisional' | 'insufficient_dust'`; `craftDecision(input: { currentTier: CardTier; ownsAnyCopy: boolean; isBoosterEligible: boolean; dust: number }): { cost: number | null; allowed: boolean; reason: CraftBlock | null }` (checks in that order).
    - `type FoilUpgradeBlock = 'no_normal' | 'foil_owned' | 'insufficient_dust'`; `foilUpgradeDecision(input: { currentTier: CardTier; ownsNormal: boolean; ownsFoil: boolean; dust: number }): { cost: number; allowed: boolean; reason: FoilUpgradeBlock | null }`.
  - `booster-stock.ts`: `interface BoosterCadence { intervalMinutes: number; maxStock: number; joinGift: number }`; `DEFAULT_BOOSTER_CADENCE: BoosterCadence = { intervalMinutes: 240, maxStock: 6, joinGift: 2 }`; `interface BoosterStockState { stock: number; anchor: Date }`;
    - `computeBoosterStock(state: BoosterStockState, now: Date, cadence: BoosterCadence): { available: number; anchor: Date; nextAt: Date | null }` — `elapsed = max(0, floor((now − anchor) / interval))`; if `state.stock >= maxStock` → `{ available: state.stock, anchor: now, nextAt: null }` (a stock above the max after a settings change is kept, not reduced); else `available = min(maxStock, stock + elapsed)`; when `available === maxStock` → anchor `now`, `nextAt` null; else anchor `anchor + elapsed × interval`, `nextAt = anchor' + interval`.
    - `consumeBooster(state, now, cadence): BoosterStockState | null` — null when `available < 1`; else `{ stock: available − 1, anchor: computed anchor }` (leaving the max starts the timer at `now`).
  - `pity.ts`: `interface PityState { sinceEpic: number; sinceLegendary: number }`; `PITY_EPIC_AFTER = 10`; `PITY_LEGENDARY_AFTER = 25`; `PITY_LEGENDARY_STEP_PERCENT = 1`;
    - `isEpicGuaranteed(p): boolean` — `p.sinceEpic >= PITY_EPIC_AFTER − 1` (at most 10 boosters in a row without Epic+, the 10th is guaranteed)
    - `legendaryBonusPercent(p): number` — `max(0, p.sinceLegendary − PITY_LEGENDARY_AFTER + 1) × PITY_LEGENDARY_STEP_PERCENT` (the 26th booster without Legendary gets +1 %)
    - `pitySummary(p): { epicGuaranteeIn: number; epicProgress: number; legendaryBonusPercent: number }` — `epicGuaranteeIn = max(1, PITY_EPIC_AFTER − p.sinceEpic)`, `epicProgress = min(1, p.sinceEpic / PITY_EPIC_AFTER)`
    - `nextPityState(p, mintedTiers: readonly CardTier[]): PityState` — any `isTierAtLeast(t,'epic')` → `sinceEpic: 0` else `+1`; any `isTierAtLeast(t,'legendary')` (Mythic included) → `sinceLegendary: 0` else `+1`.
  - `reactions.ts`: `REACTION_TYPES = ['fire','heart','star'] as const`; `type ReactionType`; `canReact(input: { isAuthor: boolean; ownsCopy: boolean }): boolean` (`!isAuthor && ownsCopy`).

    - `DROP_TABLE_VERSION = 1`; `FOIL_ODDS = 15`
    - `type TierWeights = Readonly<Partial<Record<CardTier, number>>>` (integer percents)

    - `interface PoolCard { cardId: string; authorId: string | null; number: number; tier: CardTier }`
    - `resolveTierWithFallback(rolled: CardTier, available: ReadonlySet<CardTier>): CardTier | null` — the rolled tier, else the nearest lower tier present, else the nearest higher tier present, else null.
    - `pickFromTier(cards: readonly PoolCard[], random: RandomSource): PoolCard` — authors = distinct `authorId` (null mapped to `''`) sorted ascending, `nextInt(authors.length)`; then that author's cards sorted by `number`, `nextInt(count)`. Both calls always happen (even with one candidate).
